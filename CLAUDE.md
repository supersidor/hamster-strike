# CLAUDE.md

## Rule

After every change to the game, update this file in the same change so it still describes the code (map legend, mechanics, architecture, commands).

## What this is

Browser port (three.js + Vite, plain JS modules, no physics engine) of the Godot game in `../petro3d` ("Counter-Hamster 3D"). Gameplay, constants, maps and AI are ported 1:1; when the Godot game changes, re-run `npm run assets` and port the matching script. The tile map format, legend and rules are documented in `../petro3d/CLAUDE.md`; the `.txt` map files in `src/maps/` are copies of `../petro3d/maps/`. The web version also has mesh maps (see below); `0_de_dust2` is one and is the default map (map 1 on the title screen).

## Commands

```bash
npm run dev       # vite dev server; /?debug stays solo, skips pointer lock and exposes window.cs = { Game, world, THREE, Input, Audio, renderer, hud }
npm run build     # dist/, static, relative paths
npm run server    # node server/index.mjs on :8080 (online room + serves dist/); vite proxies /ws to it, so run both for online dev
npm run check     # tools/check.mjs (every map: markers, sizes, slopes, reachability incl. sites and route waypoints, collision/raycast/flow-field-walk, King walk to both sites) + tools/net-test.mjs (headless 2-player room matches on every map)
npm run assets    # tools/convert-assets.sh: PNG -> WebP, WAV -> mono 32 kHz WAV, FBX -> weapons.json/.bin, copies maps into src/maps, then runs `npm run map`
npm run map       # tools/convert-maps.sh: every mapsrc/<map>/ -> public/maps/<dir>/*.webp + src/maps/<file>.json/.bin (extra args go to convert-map.mjs, e.g. --preview /tmp/nav.png)
```

A `Makefile` wraps these for local testing: `make dev` (no game server, so the page falls back to solo), `make debug` (opens `/?debug`), `make online` (game server + vite together), `make serve` (build + production server on :8080), `make build`, `make check`, `make assets`, `make ak47`, `make dog`, `make dogsounds`; `make help` lists them.

`make ak47` (`tools/convert-ak47.sh [zip]`, default `~/Downloads/ak-47-assault-rifle.zip`) converts the detailed AK-47: `tools/convert-gun.mjs <obj> <outbase> <name>` merges the OBJ groups, re-axes them to the FBX weapon layout (length on +X with the muzzle at max x, up on +Z) and writes `public/weapons/ak47.json/.bin` (same manifest format as `weapons.json`, mesh `AK47`); the PBR textures become `public/weapons/ak47_{albedo,normal}.webp` (2048) and `ak47_{ao,roughness,metallic}.webp` (1024). Only these outputs are committed, not the zip.

`make dog` (`tools/convert-dog.sh [zip]`, default `~/Downloads/dog.zip`) converts the dog: `tools/convert-dog.mjs <glb> <outbase> [albedo.png]` reads the single static mesh of the GLB by hand, applies the node transform, turns it 180° so the head points to -Z, puts the feet at y 0, centres it and scales the length to 1.5 m, and writes `public/models/dog.json/.bin` (manifest format of the weapons, mesh `Dog`); the albedo is the `KHR_materials_pbrSpecularGlossiness` diffuse texture (not the fallback base colour), saved as `public/models/dog_albedo.webp` (1024). `assets.dog` is `{geometry, material}` (the texture needs `flipY = false`, glTF UVs).

`make dogsounds` (`tools/convert-dogsounds.sh`) downloads the CC0 / public-domain / CC-BY sources (OpenGameArt dog packs, the U.S. Fish and Wildlife wolf howls) into a temp dir, converts them with `afconvert` and runs `tools/cut-dogsounds.mjs`, which splits long recordings by loudness, trims, normalises, fades, pitch-shifts a few copies and writes 10 variants of each of `bark`, `growl`, `whine`, `howl` as `public/dog/<kind>_<1..10>.wav` plus `index.json` and `CREDITS.md`. They live in `public/dog/` (not `public/sounds/`, which `npm run assets` wipes); `Audio.load` reads both indexes and stores the dog clips as `dog_<kind>_<n>`.

## Deploy

Runs on the k3s homelab. A push triggers `.github/workflows/push.yaml` (`npm run check`, then a multi-arch image `supersidor/hamster-strike:<short sha>` on Docker Hub). The `Dockerfile` builds `dist/` with Node, then runs `node server/index.mjs` (port 8080) in `node:22-alpine`: it serves `dist/` (same cache headers as the old nginx) and the `/ws` WebSocket of the single online room. `chart/` is a minimal Helm chart (Deployment with `replicas: 1` and `Recreate`, because the room lives in memory; Service; Ingress at `hamster-strike.homelab` with 3600 s proxy timeouts for the WebSocket); the ArgoCD Application lives in `~/hobby/argocd/apps/services/hamster-strike.yaml` and passes `image.tag=$ARGOCD_APP_REVISION_SHORT`. The public hostname is added by hand in the Cloudflare tunnel dashboard, pointing at `http://hamster-strike.hamster-strike.svc.cluster.local:80` (the tunnel passes WebSockets).

`tools/bot-test.js` is an aimbot that plays whole solo matches in the page: with the dev server running, open `/?debug` and run `eval(await (await fetch('/tools/bot-test.js')).text())` in the console (or through the browser tool); it returns a JSON report (rounds, kills, kinds seen, errors). Run it on all maps after touching game logic. `tools/bot-client.mjs [ws url] [name] [seconds] [weapon] [autostart]` is a headless online teammate (joins, readies, shoots nearby hamsters). A hidden browser tab gets no `requestAnimationFrame`; on `/?debug` use `await cs.drive(seconds, hook)` to step the frame loop manually.

## Mesh maps

A mesh map is a real triangle mesh (de_dust2 is the CS 1.6 BSP exported to OBJ by Crafty) instead of a tile grid. Sources live in `mapsrc/<map>/`: the `.obj`/`.mtl`, `textures/*.png` and a hand-written `map.json` (`name`, output `file` and texture `dir`, `scale` 0.0254 m per unit, nav `cell` size, `navRadius`, `stepUp`, `sky`, `walls`, `fog`, `nonSolid` OBJ groups (the dust2 lamps), and `markers` in source x/y: `P`, `T[]`, `K`, `A`, `B`, `routes[3]`).

- `tools/convert-map.mjs <srcdir> <outbase> [--preview png] [--probe c,r] [--groups]` converts to game space (`(x, z, -y) * scale`, centred on the XZ origin, lowest walkable floor at y 0), writes `<outbase>.bin` (Float32 positions, Float32 uvs, Uint32 render index grouped by material, Uint32 solid index) and `<outbase>.json` (materials, counts, markers as nav cells, nav grid). It bakes the **nav grid** with `three-mesh-bvh`: per cell, floors are upward faces hit by a down ray with `PLAYER_H` headroom; a flood fill from `P` and the `T` markers keeps the reachable floor (one per cell; overlaps are reported as conflicts) and links two neighbours only when a simulated walk with `MeshCollision` at `navRadius` gets across both ways. `kingLinks` repeats the walk at `BOSS_WALL_R`. `--preview` writes a top-down PNG (reached floors by height, unreached open floors blue, unlinked edges red, markers); `--probe` prints the down-ray hits of one cell; `--groups` lists OBJ groups with bounds.
- `src/meshmap.js` `parseMeshMap(json, arrayBuffer)` returns a map entry (geometry, nav, markers) with a `MeshBVH` of the solid triangles. The browser loads `src/maps/*.json` + `*.bin` in `main.js`, the server and tools through `server/maps.mjs` `loadMapEntries()`. All `src/maps/*.txt` and `*.json` are sorted by file name into one list, so client and server agree on map indices.
- `Level` (`kind: 'mesh'`) builds synthetic `rows` from the nav grid (`#` closed, `.` open, marker chars), so markers, flow fields, `steer`, the radar and the room code work unchanged. `tile` is the nav cell size, `linked` reads the baked link bits (`flowField(c, r, links)` / `flowFieldMulti(seeds, links)` take another link set and tag the result, `steer` uses the tag), `heightAt(x, z, y)` is a BVH down ray from just above `y` (or the nav height), `stepUp` replaces the player's 0.3 m step (0.46 m = GoldSrc's 18 units), and `wallRadius` (the nav radius) caps hamster wall colliders.
- `MeshCollision` (`src/meshCollide.js`, extends `Collision`): `raycast` is `raycastFirst`, `probe` clips each nearby triangle to the slab `(feet + climb, feet + PLAYER_H)` and tests it against the circle in XZ, `support` is the highest down-ray hit at the centre and 8 ring points, `ceiling` the lowest up-ray hit (the player stops jumping into it; tile `Collision.ceiling` is `Infinity`). `SimWorld.loadMap` switches between the two collisions, so always use `world.collision`, never a cached one.
- `Game.siteFlow` (carriers) uses normal links; `Game.kingFlow` (to the site) and `Game.kingChase` (after the plant) use `kingLinks`.
- `src/meshLevel.js` renders it as one mesh with a `MeshStandardMaterial` per OBJ material (WebP textures from `public/maps/<dir>/`, repeat wrap) plus the bombsite labels from `levelMesh.js`. There are no lightmaps; the usual sun, fill and hemisphere lights light it.

## Online co-op

The page joins the one public room on load (`?name=Alice`, `?server=ws://host/ws`; `?solo` or `?debug` stay offline; if the server is unreachable or you leave with X it shows the solo title screen, where O joins again): 2-8 Petros fight the same hamster waves and King (no friendly fire). Waves are `ROUND_WAVES * (1 + COOP_WAVE * (n-1))`, King HP `BOSS_HP * (1 + COOP_BOSS * (n-1))` (n = living players at round start). The CT side loses when everyone is dead, the bomb explodes or time runs out. Anyone can pick the map / start in `title` and `match_end`; in `buy` the round goes live when all players pressed Space or the timer ends. Someone joining mid-round plays right away: they spawn alive on a free spot next to the first living teammate (`spawnSpots(2, mate.position)`, same floor), with the default USP; dead players spectate (click cycles teammates) until the next freeze. When the room empties it returns to `title`.

- **Roles** (`Game.role`): `solo` (everything local), `server` (headless authority, `Game.visual = false`), `client` (`Game.authority = false`: only animates replicas). `Game.sink` (server) emits events, `Game.out` (client) sends messages; `Game.feedback(soldier, msg)` is the per-player cue (hit marker, kill streak, hurt, death loadout reset) and runs locally in solo.
- **Authority**: the client owns its own movement, aim, weapons, ammo and hitscan and sends `s` (30 Hz state), `hit {id, w, hs, d}` / `hit {k:1,...}` for the King, `ignite`, `shot` (relayed as tracers/muzzle flash), `woof {n, v}` (dog sound, see below), `nade`, `buy`, `ready`, `map`, `start`, `ping`. The `s` message also carries `dg` (1 = dog mode, toggled with H while playing, cosmetic only); the server stores it in `Soldier.dog` and puts it at index 19 of the soldier row, and `Avatar.setDog` swaps the Petro body for the dog (`Avatar.pose(..., dog)`), wearing a harness (two girth straps with buckles, a back strap and a metal mount plate, built in `dogHarness()`) with the gun lying on the plate. In dog mode (alive, playing) Z / X / V / B play a bark / growl / whine / howl (`D.DOG_SOUNDS`, 0.4 s cooldown, a random one of `D.DOG_VARIANTS` = 10 clips, never the same twice in a row): `Player.woof` plays it locally and sends `woof {n: kind, v: variant}`; `Room.onWoof` checks hp, `dog`, kind, variant and a rate limit and relays `{t: 'woof', id, n, v}` to the others, `Net.remoteWoof` plays it with `Audio.playAt` at the teammate's position. The server owns hamsters, King, nuts, grenade damage, barrels, bomb, defuse progress, hp/armor/kit/score and all timers; damage comes from `D.WEAPONS[w]`, never from the client. Hits are range- and rate-checked (`Room.onHit`), names are sanitised, JSON frames max 16 KB, 200 msg/s per client.
- **Wire**: server -> client frames are `{e: [events], s?: snapshot}` (events in order, snapshot at 20 Hz: phase/timer/score, soldier rows, hamster/King rows; `src/protocol.js`). Events: `place newmatch map freeze live rend clear mend hs hd hh hm ks kh kd ns nx gs sm bp bx ex snd say feed shake fb shot woof pong`. A late joiner first gets a `welcome` (map, removed barrels, live hamsters/King/smokes/bomb). Clients draw entities ~100 ms in the past (`Track` interpolation in `net.js`).
- **Server code**: `server/headless.mjs` shims `document` and `Audio` (sounds become `snd` events), builds hamster texture stubs from `public/hamsters/rects.json` (visible rects, generated by `tools/hamster-rects.mjs` from the Godot PNGs; the client uses the same file so hitboxes match) and defines `ServerWorld` (a `SimWorld` that emits spawn events and skips corpses/visuals). `server/room.mjs` is the room (tick loop at fixed 1/120 s, validation, welcome). `server/index.mjs` is HTTP + WebSocket.
- **Sim/render split**: `simworld.js` (`SimWorld`: level, collision, entity lists, spawn helpers, soldier placement) is extended by `world.js` (`World`: scene, lights, effects, viewmodel player, barrels, bomb visual). Hamster/King `update` runs `think` (only if `Game.authority`) and `animate` (only if `Game.visual`); nuts/grenades only damage when `Game.authority`. `Soldier` (`soldier.js`) holds per-player state; `Game.hp/armor/kit/kills/...` are accessors onto `Game.me`, and `Game.target(pos)` is the nearest living soldier used by hamster/King AI. `Level.flowFieldMulti` seeds the flow field from every living soldier.

## Architecture (`src/`)

- `data.js` constants (metres, `WEAPONS`, `HAMSTER_KINDS`, ...). Keys are `KeyboardEvent.code` strings.
- `level.js` pure map logic (no DOM): parse, heights/slopes, `heightAt`, `footing`, `linked`, BFS `flowField`, `steer`, `touching`, plus the mesh map branch (see Mesh maps). Tiles are `[c, r]`; barrel fuses are keyed by `r * cols + c`.
- `collide.js` `Collision`: convex solids per tile for rays (`raycast(from, to, sightOnly)` with a tile DDA; `sightOnly` ignores sandbags; barrels are cylinders and come back as `hit.barrel`), and circle-vs-tile movement (`probe`, `moveCircle`, `support`): a tile blocks when its surface at the nearest point is higher than `feet + climb`, so jumping one step, stairs, ramps and crate tops work without a physics engine. Players use climb 0.3, hamsters and the King `MAX_CLIMB`.
- `levelMesh.js` builds the whole map as one vertex-coloured mesh (noise texture, trims, stairs, ramps) plus bombsite labels.
- `game.js` the `Game` singleton (port of `autoload/game.gd`, extended for several soldiers): phase machine `title → buy → live → round_end → match_end`, rules, spawning, bomb, barrel fuses. `world.js` owns the scene, lights (sun with a player-following shadow frustum, fill, hemisphere, a few permanent point lights to avoid shader recompiles), the effect helpers and the barrel/bomb visuals; entity lists (`hamsters` holds only living ones, corpses live in `corpses`) and spawn helpers are in `simworld.js`.
- `player.js` input, movement, recoil, hitscan (ray vs world, hamster/king cylinders, pierce for the AWP; online it sends hits instead of applying damage) and the viewmodel; `entities/*.js` hamster, king, nut, grenade (own bounce physics via `raycast`), smoke, bomb, barrel, avatar (teammate: Petro face billboard, blue body, gun, name label). `net.js` the browser side of online play (`Net`), `soldier.js`, `protocol.js` and `simworld.js` as described under Online co-op.
- `effects.js` pooled instanced particles, decals, tracers, floating text, explosion light; `sky.js` the cloud sky shader; `audio.js` WebAudio (3D via `PannerNode`); `hud.js` DOM overlay plus a crosshair canvas and the radar; `assets.js` loads textures (computes each hamster's visible rect), weapon meshes (`weapons` and `ak47` manifests into `weaponMeshes`), `gunMaterial` (the shared palette) and `weaponMaterials` (per model PBR materials, today only `AK47`; the viewmodel and avatars use it when the weapon's `model` has one, else the palette with the optional tint), the canister and sounds; `main.js` renderer, fixed 120 Hz simulation step, pause while the pointer is unlocked.
- Fog uses Godot's exponential falloff (the `fog_fragment` chunk is patched in `main.js`). Light intensities are Godot energy × π.
- Differences from the Godot version: no SSAO/glow, decals are quads on the hit surface, crouch is Ctrl or C (browsers eat Ctrl+W), the game pauses when the mouse is released (not online), fullscreen is the browser's (F11), the AK-47 uses a detailed textured model (the other rifles keep the low-poly `Gun-AK47`), online co-op, mesh maps (de_dust2) and the H dog mode (teammates see you as a dog) exist only in the web version.
